# Reel Remote

Control Instagram Reels navigation on your Android phone from your Windows laptop.

Three commands, nothing else:

| Global hotkey    | In the controller window | Command      | What the phone does                                  |
|------------------|--------------------------|--------------|------------------------------------------------------|
| `Ctrl+Alt+Up`    | `Up`                     | `NEXT`       | Swipe up (50% width, 75% height → 50% width, 25% height) |
| `Ctrl+Alt+Down`  | `Down`                   | `PREVIOUS`   | The exact opposite swipe                             |
| `Ctrl+Alt+Space` | `Space`                  | `PLAY_PAUSE` | Single tap at the centre of the screen               |
| `Ctrl+Alt+Q`     | `Esc`                    | —            | Disconnect                                           |

Or drive it entirely from the mouse:

| Mouse (system-wide)      | Command      |
|--------------------------|--------------|
| `Alt+Shift+wheel down`   | `NEXT`       |
| `Alt+Shift+wheel up`     | `PREVIOUS`   |
| `Alt+Shift+middle click` | `PLAY_PAUSE` |

Or just click. The controller has three real buttons — **▲ NEXT**, **PLAY / PAUSE**,
**▼ PREVIOUS** — greyed out while disconnected so the state is never ambiguous. Two options
sit under them:

* **Always on top** — pins the whole controller window above other windows.
* **Mini remote** — pops out a small always-on-top pad containing *only* the three buttons
  and a connection line. Park it in a corner and click away while the browser has focus.

Both are remembered between runs, and the mini remote reopens on launch if you left it open.

The global combos use modifiers deliberately: nothing types `Ctrl+Alt+Space` or holds
`Alt+Shift` while scrolling by accident, so they need no blanket key suppression and never
steal input from the app you are actually using. That is why **both global hotkeys and the
wheel are armed by default**. Pick a different modifier, the old bare-key behaviour, or
**your own combinations** from the **Hotkeys** dropdown.

There is **no screen mirroring, no remote desktop, no Instagram login, no reading of
Instagram content, and no scraping**. The phone app performs three gestures on request and
does nothing else. It has no outbound network code at all.

## 2. Communication protocol

HTTP/1.1 over the local network, JSON both ways. Chosen over WebSocket because the phone
side then needs zero dependencies (the server is ~300 lines of `java.net` + `org.json`) and
each command is a self-contained, idempotent request — there is no stream to keep alive.
Connection liveness is covered by polling `/ping` every 3 seconds.

**`GET /ping`** — used for connect and heartbeat.

```
GET /ping HTTP/1.1
X-Auth-Token: <token>
```
```json
{
  "ok": true, "app": "reelremote", "protocol": 1,
  "accessibility": true, "screen_on": true, "locked": false,
  "foreground_package": "com.instagram.android",
  "target_package": "com.instagram.android",
  "target_foreground": true,
  "require_target_foreground": true,
  "port": 8787
}
```

**`POST /command`**

```
POST /command HTTP/1.1
Content-Type: application/json

{"token": "<token>", "command": "NEXT"}
```
```json
{"ok": true, "command": "NEXT"}
```

The token may be sent in the JSON body **or** as an `X-Auth-Token` header; both endpoints
accept either.

### Error responses

| HTTP | `error`                  | Meaning                                              |
|------|--------------------------|------------------------------------------------------|
| 400  | `BAD_JSON` / `BAD_REQUEST` | Body is not JSON, or `/command` had no body        |
| 400  | `UNKNOWN_COMMAND`        | Not one of `NEXT`, `PREVIOUS`, `PLAY_PAUSE`          |
| 401  | `UNAUTHORIZED`           | Wrong or missing pairing token                       |
| 403  | `FORBIDDEN_NETWORK`      | Client IP is not on a private/local network          |
| 404  | `NOT_FOUND`              | Unknown endpoint                                     |
| 405  | `METHOD_NOT_ALLOWED`     | `/command` reached with something other than POST    |
| 409  | `SCREEN_OFF`             | Phone screen is off                                  |
| 409  | `SCREEN_LOCKED`          | Phone is on the lock screen                          |
| 409  | `TARGET_NOT_FOREGROUND`  | Instagram is not the foreground app                  |
| 409  | `FOREGROUND_UNKNOWN`     | No window change observed yet since enabling         |
| 409  | `GESTURE_FAILED`         | The system rejected or cancelled the gesture         |
| 413  | `PAYLOAD_TOO_LARGE`      | Body over 4 KB                                       |
| 429  | `RATE_LIMITED`           | Includes `retry_after_ms`                            |
| 429  | `AUTH_THROTTLED`         | 10+ bad tokens from that IP in 60 s                  |
| 500  | `NO_SCREEN_METRICS`      | Screen dimensions unreadable                         |

### Rate limiting (phone side)

* Minimum 150 ms between accepted commands.
* Maximum 25 commands per rolling 5 s window.
* 10 failed token attempts from one IP within 60 s blocks that IP for the rest of the window.

The controller additionally refuses to send faster than one command per 200 ms, which is
what swallows the OS key-repeat storm when you hold an arrow key down.

## 3. Security

* The server binds a TCP socket for the LAN, and then **rejects any request whose source
  address is not private** (RFC1918 / link-local / loopback). A request arriving from a
  routable public address is answered with `403` before the token is even examined.
* A 16-character random pairing token (`SecureRandom`, ambiguous characters removed) is
  generated on first launch and required by every request. Comparison is length-checked and
  constant-time over the characters.
* Nothing is exposed to the internet unless you deliberately port-forward the port on your
  router — **don't**. There is no UPnP, no NAT traversal and no outbound connection anywhere
  in the app.
* `android:allowBackup="false"` keeps the token out of cloud backups.
* The accessibility service declares `canRetrieveWindowContent="false"`. It cannot read the
  screen even if it wanted to; the only thing it observes is the **package name** of
  whichever window came to the front, purely to refuse gestures when Instagram is not open.

**What the token actually protects against:** someone else on your Wi-Fi (a guest, a
compromised smart TV) sending swipes to your phone. It is not a defence against someone who
already controls your laptop or phone. Traffic is plain HTTP — a hostile device on the same
LAN doing ARP spoofing could read the token. That is an accepted trade-off for a
three-command LAN toy; regenerate the token in the app if you ever suspect it leaked.

### About the `keyboard` package

Tkinter can only see keystrokes while its own window is focused. The **`keyboard`** package
installs a low-level Windows keyboard hook (`WH_KEYBOARD_LL`), which is the only practical
way to catch Up / Down / Space while you are looking at something else on the laptop. It
also supports `suppress=True`, so those keys do not leak into whatever app is focused.

It is **optional**. Without it the controller still runs; the hotkeys just require the
controller window to be focused. Two caveats: some antivirus products flag low-level
keyboard hooks, and a few machines need the controller run as Administrator.

### Hotkey presets

Pick one from the **Hotkeys** dropdown. Your choice is remembered.

| Preset | NEXT / PREVIOUS / PLAY_PAUSE / disconnect | Suppresses keys? |
|---|---|---|
| **Ctrl+Alt** (default) | `ctrl+alt+up` `ctrl+alt+down` `ctrl+alt+space` `ctrl+alt+q` | No |
| Ctrl+Shift | `ctrl+shift+up` `ctrl+shift+down` `ctrl+shift+space` `ctrl+shift+q` | No |
| Win+Alt | `windows+alt+up` `windows+alt+down` `windows+alt+space` `windows+alt+q` | No |
| Custom… | whatever you bind | Only if you bind a bare key |
| Plain keys | `up` `down` `space` `esc` | **Yes** |

The three modifier presets do not suppress anything, so they are safe to leave armed all
day and stay armed across disconnects.

### Your own shortcuts

Press **Edit…** next to the dropdown (this switches the preset to *Custom…*, seeded from
whatever preset was showing). You get one row per command:

* **Record** — press the combination you want and it is captured verbatim.
* Or type it directly: lowercase names joined by `+`, e.g. `ctrl+alt+j`, `ctrl+shift+f9`,
  `windows+numpad_add`.

Saving validates every combo, rejects duplicates, and refuses to leave a command unbound.
Suppression is then *derived*, not chosen: a binding with no `+` is a bare key and gets
suppressed; anything with a modifier does not. Bind `j` and it will be swallowed
system-wide; bind `ctrl+alt+j` and it will not.

The same dialog holds the wheel settings: which modifiers arm it, and **Invert wheel
direction** if you would rather scroll up for the next Reel.

### Mouse wheel

Holding the wheel modifiers (default `Alt+Shift`) turns the wheel into Reel navigation and
**swallows that scroll event**, so the page under your cursor does not scroll at the same
time. Let go of the modifiers and the wheel behaves completely normally — the hook only
intercepts when the exact modifier set is held, nothing more.

This is implemented as a raw `WH_MOUSE_LL` hook via `ctypes`, not a third-party mouse
library, for exactly that reason: the common Python mouse packages cannot suppress an event,
which would leave you scrolling the page and the Reel at once. It adds **no new dependency**
and it is Windows-only — the tickbox is disabled elsewhere.

**Caveat:** if you have more than one keyboard layout installed, Windows may use `Alt+Shift`
to switch input language. If your layout flips while you scroll, change the wheel modifiers
to `ctrl+alt` in the Edit… dialog (or remap the layout shortcut in Windows settings).

**"Plain keys" is the old behaviour and it is different in kind.** Bare `Space` has to be
suppressed — otherwise every space you type would also pause the Reel — and that suppression
swallows Up / Down / Space in *every* application. So it never arms itself: selecting it
un-ticks *Global hotkeys* and makes you re-tick it deliberately, and disconnecting releases
it automatically. `Esc` is never suppressed, so it always gets you out.

**Known conflict:** on laptops with older Intel HD Graphics drivers, `Ctrl+Alt+Arrow` is the
screen-rotation shortcut. If your display rotates instead of the Reel advancing, switch to
the **Ctrl+Shift** preset (or disable the hotkeys in the Intel Graphics Command Center).

Regardless of preset, plain `Up` / `Down` / `Space` / `Esc` always work while the controller
window itself is focused.

## 7. First-time pairing steps

1. Put the phone and the laptop on the **same Wi-Fi network**. If your router has "AP
   isolation" / "client isolation" enabled, turn it off — it blocks device-to-device traffic.
2. On the phone, open **Reel Remote**.
3. Tap **Open accessibility settings** → *Installed apps* / *Downloaded apps* →
   **Reel Remote gestures** → turn it **On** → confirm the system warning.
   (Some OEMs — Xiaomi, Oppo, Vivo — hide this under *Additional settings → Accessibility*.)
4. Back in the app, the top line should read **Accessibility service: ENABLED**.
5. Press **Start server**. The card now shows something like:
   ```
   IP   192.168.1.42
   Port 8787
   URL  http://192.168.1.42:8787/command
   ```
6. Note the 16-character **pairing token** (tap *Copy token* if you want to send it to
   yourself).
7. On the laptop, run the controller. Type the IP, the port `8787`, and the token.
   *(Or leave the IP blank, enter the token, and press **Find phone** to scan the subnet.)*
8. Press **Connect**. The dot turns green and the log shows `Connected`.
9. On the phone, open **Instagram → Reels**.
10. Global hotkeys and the wheel are already armed, so you can leave the controller window
    behind. Press:
    * **Ctrl+Alt+Up** → the phone swipes up to the next Reel, log shows `NEXT sent`
    * **Ctrl+Alt+Down** → previous Reel
    * **Ctrl+Alt+Space** → tap in the centre, play/pause
    * **Ctrl+Alt+Q** → `Disconnected (disconnect hotkey pressed)`

    Or hands-on-mouse: hold **Alt+Shift** and scroll down / up, middle-click to pause.

    Or click the **▲ NEXT** / **PLAY / PAUSE** / **▼ PREVIOUS** buttons. Press
    **Mini remote** for a small pad that floats above everything else.

    With the controller window focused, plain **Up / Down / Space / Esc** work too.

Settings (IP, port, token) are remembered in
`%APPDATA%\ReelRemote\controller.json`, so subsequent runs are just *Connect*.

### Tuning the gesture geometry

If a swipe overshoots by two Reels, or the centre tap opens a comment sheet instead of
pausing, adjust **section 4** in the phone app. Everything is a percentage of the screen, so
the same numbers work on any device:

| Field      | Default | Effect                                       |
|------------|---------|----------------------------------------------|
| Swipe X %  | 50      | Horizontal line the swipe travels along      |
| Start Y %  | 75      | Where `NEXT` starts (and `PREVIOUS` ends)    |
| End Y %    | 25      | Where `NEXT` ends (and `PREVIOUS` starts)    |
| Swipe ms   | 220     | Longer = gentler. Raise this if it overshoots |
| Tap X/Y %  | 50 / 50 | Where `PLAY_PAUSE` taps                      |

Press **Save**. No restart needed — the next command uses the new values.

## 8. Behaviour in the awkward cases

| Situation | What happens |
|---|---|
| **Accessibility service disabled** | *Start server* refuses with a toast. If you disable it while running, `onUnbind` stops the server and the controller drops to "Disconnected" within ~6 s. |
| **Phone screen locked or off** | Commands are refused with `409 SCREEN_LOCKED` / `SCREEN_OFF`. The controller logs `NEXT refused: SCREEN_LOCKED`. Gestures behind a keyguard would not reach Instagram anyway. |
| **Instagram not in the foreground** | Refused with `409 TARGET_NOT_FOREGROUND` and the name of the app that actually is in front. Untick *Only act while Instagram is the foreground app* if you want gestures anywhere. |
| **Foreground app not detected yet** | Right after enabling the service, no window change has been observed. First command returns `FOREGROUND_UNKNOWN`; switching apps once on the phone fixes it permanently. |
| **Network drops** | The controller's 3 s heartbeat notices after two consecutive failures and disconnects. Nothing is queued or replayed. |
| **Phone IP changes** (DHCP lease) | With *Auto re-find on drop* ticked, the controller scans your /24 with the same token, reconnects and updates the IP field. Otherwise press **Find phone**. |
| **Server already running** | *Start server* is a no-op if the socket is already bound; the button reads *Stop server* whenever it is. If another app owns the port you get `Port 8787 is already in use` — change the port field and start again. |
| **Malformed commands** | Non-JSON → `400 BAD_JSON`. Unknown command string → `400 UNKNOWN_COMMAND`. Oversized body → `413`. Nothing is dispatched. |
| **Flooded commands** | Phone: 150 ms floor and 25-per-5 s ceiling, returning `429` with `retry_after_ms`. Controller: 200 ms floor plus a 6-slot send queue that drops overflow rather than backing up. |
| **Android background restrictions** | The server lives inside the accessibility service, which the system keeps bound for as long as it is enabled. That is why there is no foreground-service notification and no `FOREGROUND_SERVICE` permission — and why the listener survives you leaving the Reel Remote app for Instagram. |
| **Reboot** | Android disables accessibility services for sideloaded apps on some OEM builds. Re-enable it in settings; the server then restarts by itself because the app remembers you had it on. |

## 9. Troubleshooting connection problems

**"Cannot reach 192.168.x.x:8787"**

1. Confirm the app says **Server: RUNNING** and re-read the IP — phones change address
   between Wi-Fi sessions.
2. Confirm both devices are on the *same* SSID. A 2.4 GHz and 5 GHz band of the same router
   are usually fine; a guest network is not.
3. Test from PowerShell with the phone app open:
   ```powershell
   curl.exe -H "X-Auth-Token: YOURTOKEN" http://192.168.1.42:8787/ping
   ```
   JSON back → the phone is fine, the problem is in the controller. Timeout → keep going.
4. **Router AP/client isolation** is the single most common cause. Look for "AP isolation",
   "client isolation" or "guest mode" in the router admin page and disable it.
5. Some phones sleep the Wi-Fi radio aggressively. Turn off battery optimisation for
   Reel Remote (`Settings → Apps → Reel Remote → Battery → Unrestricted`).
6. Windows firewall does **not** matter here — your laptop only makes outbound connections.

**"Rejected: wrong pairing token"** — the token is case-sensitive and 16 characters. If you
pressed *Regenerate* on the phone, the old token is dead; copy the new one.

**Connects, but every command is refused**

Read the `error` in the log:
* `TARGET_NOT_FOREGROUND` → open Instagram Reels on the phone, or untick the foreground check.
* `SCREEN_LOCKED` → unlock the phone.
* `GESTURE_FAILED` → the accessibility service lost its gesture permission; toggle it off and
  on in system settings.

**Commands land but the wrong thing happens** — tune the gesture geometry (section 7 above).
An overshoot to the next-but-one Reel means the swipe is too fast: raise *Swipe ms* to 300.

**Global hotkeys do nothing** — check the bold line under the dropdown: it shows the live
combos and whether they are `[global]` or `[this window only]`. If the dot is green and it
says `[global]`, another app has probably claimed the combo — switch presets. Failing that,
run the controller as Administrator; some antivirus tools silently block the hook.

**The screen rotates instead of the Reel advancing** — Intel graphics owns `Ctrl+Alt+Arrow`
on your machine. Switch to the **Ctrl+Shift** preset.

**Typing is broken everywhere / spaces do nothing** — you are on the **Plain keys** preset,
or you bound a bare key in *Custom…*. Bare keys are suppressed system-wide. Press `Esc`
(never suppressed), or un-tick *Global hotkeys*, or just close the controller.

**Alt+Shift+scroll does nothing** — check the second bold line is showing; if it is absent
the wheel is off, so tick *Mouse wheel*. If it is showing, another low-level hook may have
priority: close other macro/remapper tools, or run the controller as Administrator (a hook
installed by an elevated process outranks one from a normal process).

**My keyboard layout flips when I Alt+Shift+scroll** — that is the Windows language
shortcut. Change the wheel modifiers to `ctrl+alt` under *Edit…*.

**The page scrolls as well as the Reel** — the modifiers were not registered as held, so the
event was passed through rather than suppressed. Press the modifiers first, *then* scroll.

**Nothing works after an Android update** — re-enable the accessibility service; major
updates frequently reset it.

## 10. Building the controller into a standalone .exe

**Already built.** The executable is at:

```
d:\scrollup\windows\dist\ReelRemote.exe     (14.6 MB)
```

It was smoke-tested: the process launches and the GUI stays up. Double-click it — no Python

To rebuild:

```powershell
cd d:\scrollup\windows
pip install pyinstaller

pyinstaller --noconfirm --onefile --windowed `
    --name ReelRemote `
    --hidden-import keyboard `
    reel_remote_controller.py
```

Notes:

* `--windowed` hides the console window. Drop it while debugging so tracebacks are visible.
* `--onefile` makes startup ~1 s slower as it unpacks to a temp folder. Use `--onedir` for
  a faster-starting folder build.
* Windows Defender/SmartScreen may warn about an unsigned single-file exe that installs a
  keyboard hook. That is expected for an unsigned binary; click *More info → Run anyway*, or
  sign it with your own certificate.
* Add `--icon myicon.ico` if you want a custom icon.
